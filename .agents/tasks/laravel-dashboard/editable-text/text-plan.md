## Context verified during exploration (ground truth, do not re-derive)

- **PublicSiteController@home already passes `$settings = SiteSetting::allAsArray()`** to the `home` view (confirmed in `app/Http/Controllers/PublicSiteController.php`). No controller change is needed (design item 2 is a no-op confirmation).
- **SettingController@update** (`app/Http/Controllers/Admin/SettingController.php`) iterates `$request->validated()` → `SiteSetting::updateOrCreate(['key'=>$k],['value'=>$v])` → `SiteSetting::flushCache()`. New validated keys persist automatically. A key with NO rule in `SettingRequest` is dropped by `validated()` and never saved — so every seeded key MUST get a rule.
- **DB charset is `utf8mb4` / `utf8mb4_unicode_ci`** on the `mysql` connection (`config/database.php` lines 54–55). Glyphs `→` (U+2192), `❤` (U+2764), `–` (en dash), `—` (em dash) store safely. The `value` column is `text` nullable (migration `2024_01_01_000008_create_site_settings_table.php`), so `max:1000`/`max:500` fit.
- **`catalog.js`** references `#emptyState`, `#swipeHint`, `#emptyReset`, `#resultCount` **by id only** (never by wording) — their text is safe to make editable; `#emptyReset`'s click→`resetFilter` binding is preserved as long as only the text node changes.
- **home.blade.php** already has the `@php` helper block style (`$sName`, `$assetUrl`, `$flagOn`) to append the `$t` closure to; all design-cited source literals were verified present (promo bar line ~83, hero H1 line ~177, hero WA link line ~196, inventory/credit/quiz/testi headings, footer copyright line ~593, credit line ~594).
- **Routes** (`routes/web.php`): `admin.settings.edit` (GET), `admin.settings.update` (PUT/PATCH), `GET /` = `home`. Admin group is `auth`-only (no role middleware). **`register` route is intentionally removed** (`routes/auth.php`) → GET `/register` 404s (matches verification).
- **Admin credentials**: `admin@daihatsu.test` / `password` (`database/seeders/AdminUserSeeder.php`, MySQL).
- **Test framework**: PHPUnit; `phpunit.xml` runs tests on **sqlite `:memory:`** with `CACHE_STORE=array` — NOT MySQL. There is currently **no `tests/Feature` or `tests/Unit` directory**; `tests/TestCase.php` is a bare stub. The new feature test must therefore use `RefreshDatabase` and create its own data (`User::factory()` exists at `database/factories/UserFactory.php`); it must NOT rely on the MySQL-seeded admin/cars.
- **OS is Windows / PowerShell**: chain commands with `;` not `&&`. Use `php artisan migrate` (NOT `migrate:fresh`) to preserve the seeded `daihatsu_db`.

## Notes / assumptions

- **Design item 2 (controller passes `$settings`)**: verified already true — folded into item 3's prerequisites, no standalone edit.
- **Reset-to-default semantics**: clearing a field to blank is valid (`nullable`) and makes `$t()` render the seeded/inline default — i.e. "reset to default", NOT "hide". This is the design's deliberate invariant; the plan does not add any hide mechanism.
- **Test DB divergence (assumption)**: the live app runs on MySQL `daihatsu_db`, but the automated suite runs on sqlite `:memory:` per `phpunit.xml`. The feature test is written to be DB-agnostic via `RefreshDatabase` + factory-created data, so it passes under sqlite while the manual server checks exercise the real MySQL path.
- **Out of scope (per design)**: catalog filter control labels/option values (JS-coupled), `Cari`/`Reset` button labels, footer landline phone + its `tel:` href, Google Maps iframe `src`/target URL, JS-module-generated WhatsApp texts, marquee pills, nav menu item labels, compare/car-detail copy, alt/aria/iframe-title strings (except the added `footer_credit` aria-label), and all dynamic JS-filled values.
